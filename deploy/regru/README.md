# Перенос журнала на VPS REG.RU

Пакет рассчитан на PostgreSQL, GoTrue, PostgREST, Caddy и небольшой сервис управления учётными записями. База, авторизация, платный журнал и журнал КЦ работают на VPS. Текущие SQL-функции и RLS переносятся из действующей базы. Клиентский SDK копируется на тот же сервер.

Выбранная конфигурация — 2 vCPU, 2 ГБ RAM, SSD 20 ГБ, Москва. Расчёт REG.RU от 23 ноября 2026 года составляет 1169,41 ₽/месяц с публичным IP. Хранение копий REG.RU тарифицируется дополнительно. Рабочая ёмкость и время сохранений должны быть проверены после восстановления данных.

## До переключения

1. Создать VPS и получить SSH-доступ. Ограничить вход SSH ключом. Разрешить входящие 22, 80, 443. Порт базы наружу не публикуется.
2. Установить Docker Engine с Compose из официального репозитория. Установить ограничения журналов Docker и настроить обновления безопасности.
3. Скопировать проект на сервер, запустить `node deploy/regru/prepare.mjs test-journal.example.ru`. Скрипт создаёт приватный `.env` и каталог `public`, который содержит только клиентские файлы. Готовую папку можно собрать на машине с Node.js и затем передать на VPS.
4. Проверить `docker compose config --quiet`. Запустить из этой папки `docker compose up -d db accounts`. Настроить тестовый DNS и HTTPS. На первом запуске проверить совместимость версии GoTrue с таблицами Auth из источника.
5. В приватном `.source-db.env` задать переменные подключения источника `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`. Права файла 600. Выполнить `sh export-source.sh`, сохранить копию вне VPS. Этот файл и SQL-дампы содержат секреты.
6. Выполнить `sh restore.sh import/TIMESTAMP` на пустой целевой базе. При ошибке восстановления остановиться и проверить совместимость схем. Скрипт завершает импорт до запуска публичного сайта.
7. Проверить вход существующими паролями, смену пароля, сброс администратором и роль преподавателя. Чужие журналы должны оставаться недоступными. Проверить обычный журнал, платные услуги, КЦ, группы, больничные, замещения и печать. Проверить параллельные сохранения и повтор после потери ответа.
8. Настроить ежедневный запуск `backup.sh`, контроль успешного завершения и отдельную копию вне сервера. Пробно восстановить копию в отдельную базу.

## Переключение

Согласовать короткое окно обслуживания. Заблокировать запись в старую базу на сервере, чтобы открытые старые вкладки также прекратили запись. Сделать окончательный экспорт Auth и всех школьных схем, восстановить его на подготовленный сервер и сверить количество учётных записей, занятий, оценки и месячные итоги. Переключить DNS и открыть новый сайт. После смены сервера пользователям потребуется заново войти.

Откат после начала новых записей требует переноса этих записей обратно. Перед откатом нужно остановить запись и сохранить новую базу, затем сверить изменения. Исходный сервер и экспорт сохраняются до завершения проверки переноса.

Подготовка пакета не означает завершённый перенос. Покупка VPS, восстановление реальной базы, проверка на сервере и переключение DNS выполняются отдельно после получения доступа.
